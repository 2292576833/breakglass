# Phase 0 Research: 原位抛物线破壁

## 1. 前端技术路线

- **Decision**: P0 使用 Vanilla JS 与原生 CSS/SVG，不引入打包器、Preact 或 Tailwind。
- **Rationale**: 仓库没有既有前端工程。当前交付是在一个 `<video>` 上挂透明层、用 SVG 画一条抛物线，并处理暂停、拖动、重置、退出和超时。这些都可以由浏览器原生能力完成。Chrome MV3 不允许扩展加载远程可执行代码，无打包的本地脚本更容易把内容安全策略收成 `script-src 'self'`。
- **Alternatives considered**: Preact 加固定构建工具是宪法允许的另一条路线。当前没有需要组件树消化的界面规模，引入构建链不会减少坐标对齐和扩展权限的工作。Tailwind 只在 Preact 路线中可选，不能与本路线并列。

## 2. 不建设 FastAPI 或感知代理

- **Decision**: 本功能不新增服务进程、数据库或登录。真实识别与单帧上传不进入验收。
- **Rationale**: 产品宪法要求抛物线闭环在没有自建服务时可以重复演示。感知代理只有在单帧上传被书面允许、仓库边界被修订之后才能开工。用户已确认 P0 不需要 FastAPI。
- **Alternatives considered**: 用 FastAPI 代持视觉密钥。它只属于尚未获准的后续能力，不能作为本计划的依赖。

## 3. 准备结果是底子，不是假界面

- **Decision**: 播放、定位、原位曲线、拖动、重置和退出是真实交互。预先准备的是曲线数据。验收路径不发起网络识别；界面从出现到退出都标明“预先准备的示例”。
- **Rationale**: 规格要求断网仍能完成主路径，同时要求超时或失败不得显示成识别成功。准备结果与将来的识别结果使用同一份 `CurveResult` 形状，后续可以替换数据来源而不换交互层。
- **Alternatives considered**: 用永远成功的假识别填充界面。这会把准备数据说成识别成功，违反规格 SC-002。

## 4. 已验证页面放在扩展内

- **Decision**: P0 的已验证页面是扩展自带的演示页，里面有一个可访问的 `<video>`。破壁逻辑作为该页的本地脚本运行。在团队写下外部域名之前，manifest 不声明内容脚本匹配，也不请求主机权限。
- **Rationale**: 首版只承诺已验证页面。`file://` 和任意网站都不在验收内。扩展页可以离线打开，视频资源随包加载，不需要静态服务器。
- **Alternatives considered**: 先注入任意网页。宪法明确排除未验证播放器、跨域 iframe、Shadow DOM 和 DRM。本地静态服务器能提供 http 页面，但会多一个与演示无关的进程。

## 5. MV3 表面

- **Decision**: `manifest_version` 为 3。背景脚本是几乎空的 module service worker，不发起网络请求、不保存密钥。演示页动作按钮打开演示页。扩展页 CSP 为 `script-src 'self'; object-src 'self'`，不加入 `wasm-unsafe-eval`。
- **Rationale**: MV3 要求 service worker。P0 用不到它做识别或执行，保留它是为了满足扩展形态并证明没有隐藏网络调用。Pyodide 不在本功能内，因此不放宽 WASM 策略。
- **Alternatives considered**: 省略 service worker。当前 Chrome MV3 打包无法通过。给 P0 预先打开宽 CSP，会让后续远程脚本有机可乘。

## 6. 曲线公式先由素材命名

- **Decision**: 素材用 `equationId` 选择求值器，并给出具名参数、范围、步长和拖动哪一个参数。实现只注册素材里实际出现的 `equationId`。未知 id 拒绝进入交互。工程夹具可以使用 `fixture.parabola`，且必须标成夹具；它不能代替团队正式演示视频的验收。
- **Rationale**: 规格禁止把某一条代数式写成唯一公式，同时拖动又必须改变真实参数。用 id 分发可以把公式决定留在素材里，同时避免任意表达式执行。
- **Alternatives considered**: 在计划里冻结 `y = ax^2 + bx + c` 或顶点式。正式素材尚未提供，冻结会把假设写成验收事实。让素材直接携带可执行表达式，则超出确定性白名单。

## 7. 时间与对齐

- **Decision**: `time` 的单位是秒，从视频起点计算。入口可用的时间容差默认是目标时间 ±0.2 秒；正式素材可以收紧这个数字。对齐误差使用规格中的 2%，按视频内容区域较短边的 CSS 像素计算。几何计算支持 `object-fit: contain`，并读取 `object-position`。演示页默认 `contain` 与 `50% 50%`。窗口、全屏和设备像素比变化后重新计算。
- **Rationale**: 宪法要求写明时间单位，并区分帧像素、数学坐标和页面显示坐标。2% 已在规格里作为团队尚未给出绝对像素值时的验收上限。
- **Alternatives considered**: 用帧序号代替秒。播放器对外稳定的是 `currentTime`。只按播放器外框换算，无法通过黑边场景。

## 8. 等待与外部结果

- **Decision**: 每次唤醒生成新的请求编号并记录视频 id 与时间。默认配置不发起外部尝试，匹配的准备结果立即进入交互，来源为预先准备。演示配置可以把外部尝试设为“一直不返回”“返回非法结果”或“超时后才返回”，用来验收 1.5 秒回退、失败和取消。迟到结果一律丢弃。没有匹配准备结果时保留重试和退出。
- **Rationale**: 故事 1 要在无网络时立刻可演示。故事 2 要能演练超时，但不能为此接上真实识别。1.5 秒和 0.1 秒的口径沿用规格与宪法：0.1 秒从判定超时到曲线出现，不含扩展打开、视频首帧和后续增强的初始化。
- **Alternatives considered**: 所有唤醒都空等 1.5 秒再显示准备结果。这会拖慢主演示，也不能代表“没有外部请求”的准备路径。

## 9. 测试

- **Decision**: 几何、结果校验、参数限制和会话规则用 Node.js 自带测试运行，命令为 `node --test`。这些模块不访问 DOM。扩展页上的播放、拖动、画幅和键盘路径按 `quickstart.md` 手工验收。P0 不加入 Jest、Playwright 或打包器。
- **Rationale**: 纯函数可以在没有浏览器驱动的情况下锁定黑边、拒绝条件和旧结果丢弃。界面验收依赖真实视频元素，手工脚本与成功标准一一对应。新增大型测试框架对当前范围没有必要。
- **Alternatives considered**: 只用手工点选。几何边界容易在改动后回退。用 Playwright 做端到端可以后补，但不作为本计划的开工依赖。

## 10. 重置、退出与快捷键

- **Decision**: 重置恢复本次结果的初始参数并保留交互层。Esc、退出操作和点击交互层外部都结束会话，移除覆盖层和监听，视频保持暂停。唤醒键是 Alt+B，另有可见按钮。空格不用于唤醒。
- **Rationale**: 这与规格假设一致，使重置和退出可以分开验收，也避免空格与播放器暂停冲突。
- **Alternatives considered**: 退出后自动播放。README 有过这种写法，规格已明确不采用。
